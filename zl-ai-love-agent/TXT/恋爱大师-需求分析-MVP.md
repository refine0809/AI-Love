# 【恋爱大师】AI 应用 — 需求分析（MVP）

> 目标：用户在恋爱过程中遇到难题时，由 AI 提供贴心、可执行的情感指导。  
> 策略：按 **MVP 最小可行产品** 先上线核心价值，再迭代增强能力。

---

## 1. 产品定位

**一句话**：一位随时在线、懂上下文、给得出口头建议的「恋爱大师」。

**不做**：心理诊疗、相亲匹配、社交社区、完整用户体系（MVP 阶段）。

**要做**：多轮情感对话 + 固定人设 + 场景化建议 +（可选）结构化恋爱报告。

---

## 2. 目标用户与核心需求

### 2.1 用户画像（MVP 优先）

| 优先级 | 用户群体 | 典型痛点 | MVP 是否覆盖 |
|--------|----------|----------|--------------|
| P0 | 恋爱中的年轻人（18–28） | 冷战、误解、不知道怎么说 | ✅ |
| P0 | 恋爱起步者 | 表白、邀约、暧昧节奏 | ✅ |
| P1 | 异地 / 忙碌情侣 | 维系感弱、小摩擦放大 | 🔄 二期场景模板 |
| P2 | 分手 / 复合犹豫者 | 利弊难断、情绪反复 | 🔄 二期 |

### 2.2 核心需求（按重要性）

1. **即时可聊**：随时抛出烦恼，立刻得到回应  
2. **共情 + 可执行**：先理解情绪，再给 1～3 条具体话术/步骤  
3. **多轮懂上下文**：同一会话内记住关系背景，无需反复交代  
4. **安全感**：不说教、不评判；敏感话题有边界  

---

## 3. 功能范围：MVP vs 后续

### 3.1 MVP（必须交付）

| 模块 | 服务内容 | 对应技术能力 |
|------|----------|--------------|
| 恋爱对话顾问 | 固定「恋爱大师」人设，多轮情感咨询 | System Prompt + `ChatClient` |
| 会话记忆 | 同一 `chatId` 下记住近期对话 | `ChatMemory`（内存即可） |
| 场景化引导 | 覆盖表白、冷战、日常相处 3～5 个高频场景 | Prompt 模板 / 场景关键词引导 |
| 基础安全 | 拒答危险/违法内容，必要时引导求助 | 简单 System 约束或基础 Advisor |
| HTTP 接口 | 前端/调试可调用的对话 API | Spring Boot REST |

**MVP 成功标准（验收）**

- [ ] 用户用一句话描述恋爱问题，AI 能共情并给出可执行建议  
- [ ] 连续 5 轮以上对话不丢关键上下文（同 `chatId`）  
- [ ] 人设稳定：语气温暖、务实，不跑成通用百科助手  
- [ ] 提供至少一个可测的对话接口（如 `/ai/love_app/chat`）

### 3.2 一期增强（MVP 之后立刻做）

| 模块 | 服务内容 | 对应技术能力 |
|------|----------|--------------|
| 恋爱报告 | 对话后生成结构化分析报告 | Spring AI 结构化输出 |
| 自定义 Advisor | 日志、敏感词、输出润色、限流 | 自定义 `Advisor` |
| Prompt 模板外置 | 人设/场景模板可配置、可迭代 | Prompt Template 资源文件 |

### 3.3 二期（增强体验）

| 模块 | 服务内容 |
|------|----------|
| 对话记忆持久化 | 重启不丢历史；支持回访式咨询 |
| 会话管理 | 会话列表、新建/切换会话 |
| 更多场景模板 | 异地、父母压力、复合等 |
| 多模态 | 上传聊天截图，解读语气与误解点 |

### 3.4 明确不做（MVP）

- 用户注册登录、会员付费  
- 社交广场、匹配推荐  
- 真人咨询师对接  
- 复杂推荐算法 / Agent 工具调用链

## 4. 主要功能模块说明（MVP 详述）

### 4.1 恋爱对话顾问

**输入**：用户自然语言问题 + `chatId`  
**输出**：共情 + 简短分析 + 可执行建议（话术/步骤）  

**人设要点（Prompt）**

- 身份：经验丰富、温柔且务实的恋爱顾问  
- 风格：口语化、不说教、少空话  
- 结构建议：① 共情 ② 问题拆解 ③ 1～3 条行动建议 ④（可选）一句反问澄清  

### 4.2 会话记忆

- 以 `chatId` 隔离不同用户/会话，禁止串话  
- MVP：内存 `ChatMemory`，限制最近 N 轮（如 10～20）控制成本  
- 后续：自定义持久化（DB / Redis）

### 4.3 高频场景（MVP 先覆盖）

1. **表白 / 推进关系** — 时机判断、开口话术  
2. **吵架 / 冷战** — 降温、复盘、和好话术  
3. **日常相处摩擦** — 边界、期待对齐、小矛盾处理

## 5. 差异化竞争点（MVP 也要体现）

| 差异点 | MVP 如何体现 | 后续如何加强 |
|--------|--------------|--------------|
| 垂直人设 | 强 System Prompt，非通用助手 | 多场景模板库 |
| 可执行建议 | Prompt 强制「话术/步骤」输出结构 | 报告中的行动清单 |
| 有记忆陪伴 | 同会话多轮记忆 | 持久化 + 用户关系摘要 |
| 工程可控 | REST API + 可替换模型（云端/Ollama） | Advisor 链、结构化报告 |

相对通用大模型聊天：更垂直、更结构化、更可产品化嵌入。

## 6. 技术挑战与 MVP 解决方案

| 挑战 | 风险 | MVP 方案 | 后续方案 |
|------|------|----------|----------|
| 人设漂移 | 变成百科/说教 | 精炼 System Prompt + 少样例 | 自定义 Advisor 二次约束 |
| 上下文丢失 | 建议前后矛盾 | 内存 ChatMemory + 窗口截断 | 摘要记忆 + 持久化 |
| 建议空泛 | 用户觉得没用 | Prompt 要求具体话术/步骤 | 场景模板细化 |
| 敏感内容 | 合规与安全风险 | System 层拒答规则 | 安全 Advisor + 审计日志 |
| 成本与延迟 | Token 贵、响应慢 | 限制记忆轮数；可切本地 Ollama | 缓存常见问题、流式输出 |
| 会话串话 | 隐私事故 | 强制 `chatId` 隔离 | 用户维度 + DB 分区 |
| 报告格式不稳 | JSON 字段乱 | （一期）结构化输出 + 校验 | 失败重试兜底 |

**技术栈（与当前项目对齐）**

- Spring Boot 3 + Spring AI（Alibaba / Ollama）  
- `ChatClient` + `ChatMemory`  
- REST API 对外提供对话能力  
- （一期）结构化输出、自定义 Advisor、Prompt 模板  

---

## 7. MVP 开发任务拆分

建议按以下顺序实现，每步可独立验收：

```
1. Prompt 设计（恋爱大师人设 + 输出结构）
2. ChatClient 对话服务 + 内存 ChatMemory（按 chatId）
3. REST 接口：发送消息 → 返回回复
4. 手工/接口测试：3 个高频场景各跑通一轮多轮对话
5.（可选立刻跟进）恋爱报告结构化输出
6.（可选立刻跟进）基础安全 / 日志 Advisor
```

### 建议接口（MVP）

```http
GET/POST /ai/love_app/chat?message={用户问题}&chatId={会话ID}
```

响应：纯文本或统一 `BaseResponse` 包装的 AI 回复。

## 8. 非功能需求（MVP 底线）

| 类型 | 要求 |
|------|------|
| 可用性 | 单机可启动，本地或云端模型可切换 |
| 隐私 | 会话按 chatId 隔离；不在日志中打印完整隐私细节（尽量脱敏） |
| 性能 | 普通对话可接受数秒级延迟；记忆窗口可控 |
| 可维护 | Prompt 与业务代码分离（至少独立常量/资源文件） |

## 10. 结论

**MVP 只做一件事做好**：让用户带着恋爱烦恼进来，经过多轮对话，得到温暖、具体、可执行的指导。

先验证「人设 + 记忆 + 可执行建议」是否成立，再扩展报告、持久化与多模态，避免一开始做成大而全的情感平台。
